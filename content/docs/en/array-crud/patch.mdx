---
title: "4. PATCH"
description: Partially updating an item — the field is optional, and merges instead of replacing.
---

## The code

```python title="main.py"
from typing import Optional
from fastapi import FastAPI, HTTPException

app = FastAPI()

data = ["first", "second"]

@app.patch("/items/{item_index}")
def update_item(item_index: int, value: Optional[str] = None):
    if item_index < 0 or item_index >= len(data):
        raise HTTPException(status_code=404, detail="Item not found")
    if value is not None:
        data[item_index] += value
    return {"index": item_index, "value": data[item_index]}
```

## Line by line

1. **Check the index exists first** — same bounds check as
   [GET](/en/docs/array-crud/get) and
   [PUT](/en/docs/array-crud/put): `item_index < 0` rejects negative
   numbers, `item_index >= len(data)` rejects anything past the end,
   and either one raises `HTTPException(404)` before the function
   touches `data[item_index]`.
2. **`value: Optional[str] = None`** makes the query parameter optional
   — unlike [PUT](/en/docs/array-crud/put)'s `value: str`, which is
   required. That's the first difference between `PUT` and `PATCH`:
   `PUT` demands the full representation, `PATCH` lets you send only
   what changed.
3. **`data[item_index] += value`** — merges onto the existing value
   instead of overwriting it, and only runs at all if the client
   actually sent a value. Leaving `value` out of the request leaves
   the item untouched.

With a single-field item, `PUT` and `PATCH` would otherwise set the
same one field and look identical. Making `PATCH` merge instead of
replace stands in for "update only part of the resource" — which is
what `PATCH` means in real APIs, once a resource has several fields.

## Try it

```bash
curl -X PATCH "http://127.0.0.1:8000/items/0?value=-patched"
curl -X PATCH http://127.0.0.1:8000/items/1
curl -i -X PATCH http://127.0.0.1:8000/items/9  # 404
```

Expected for the first call: `{"index": 0, "value": "first-patched"}`.
