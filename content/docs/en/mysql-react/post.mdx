Start with one verb: **`POST /items`**. The backend has a single route,
and the React page adds a value and shows **only a message**
(`Item added: first`) — no list yet. [GET](/en/docs/mysql-react/get)
adds the list next.

## Backend

**`database.py`** — connection settings and the `get_db()` dependency, unchanged on every page in this topic:

```python title="database.py"
import os

from dotenv import load_dotenv
from sqlalchemy import URL, create_engine
from sqlalchemy.orm import Session, declarative_base, sessionmaker

load_dotenv()

# URL.create escapes special characters (like "@") in the password.
# Set DATABASE_URL to override it (e.g. "sqlite:///./test.db").
DATABASE_URL = os.getenv("DATABASE_URL") or URL.create(
    "mysql+pymysql",
    username=os.getenv("MYSQL_USER", "root"),
    password=os.getenv("MYSQL_PASSWORD", ""),
    host=os.getenv("MYSQL_HOST", "127.0.0.1"),
    port=int(os.getenv("MYSQL_PORT", "3306")),
    database=os.getenv("MYSQL_DB", "fastapi_learn"),
)

engine = create_engine(DATABASE_URL, pool_pre_ping=True)
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)
Base = declarative_base()


def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

**`models.py`** — the `ItemModel` table:

```python title="models.py"
from sqlalchemy import Column, Integer, String

from database import Base


class ItemModel(Base):
    __tablename__ = "crud_react_items"

    id = Column(Integer, primary_key=True, autoincrement=True)
    value = Column(String(255), nullable=False)
```

**`schemas.py`** — the request body this route validates against:

```python title="schemas.py"
class ItemRequest(BaseModel):
    value: str
```

**`crud.py`** — the insert function:

```python title="crud.py"
def create_item(db: Session, item: ItemRequest) -> ItemModel:
    row = ItemModel(value=item.value)
    db.add(row)
    db.commit()
    db.refresh(row)
    return row
```

**`main.py`** — CORS, and the route:

```python title="main.py"
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173", "http://127.0.0.1:5173", "http://localhost:3000"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)


@app.post("/items", status_code=status.HTTP_201_CREATED)
def create_item(item: ItemRequest, db: Session = Depends(get_db)):
    row = crud.create_item(db, item)
    return {"id": row.id, "value": row.value}
```

## Line by line

`database.py`'s connection settings, `models.py`'s `ItemModel` table and
the CORS setup are shared by every page in this topic — see the
[index page](/en/docs/mysql-react) for those explained line by line.
Below covers what's specific to this page: `schemas.py`'s `ItemRequest`,
`crud.py`'s `create_item`, and the route in `main.py` that calls it.

1. `class ItemRequest(BaseModel):` — a Pydantic model FastAPI uses to
   validate the incoming JSON body; a request missing `value`, sending
   the wrong type, or not sending JSON at all, is rejected with a `422`
   before this route's body ever runs.
2. `db: Session = Depends(get_db)` — this is FastAPI's dependency
   injection at work: FastAPI calls `get_db()` itself before the route
   body runs.
   - `get_db` is a generator function — notice the `yield` inside it —
     so FastAPI runs it up to that `yield`, and the value it yields (a
     fresh `SessionLocal()` instance) becomes whatever gets bound to
     the `db` parameter here.
   - Once the route returns (or raises), FastAPI resumes `get_db()`
     right after the `yield`, running its `finally: db.close()` — so
     the session always gets closed, success or failure, without this
     route needing its own `try`/`finally`.
   - Without `Depends`, every route would have to open and remember to
     close its own session by hand — and a forgotten `close()` after an
     exception quietly leaks a database connection.
3. `row = ItemModel(value=item.value)` — builds a new ORM object in
   memory; nothing is written to the database yet.
4. `db.add(row)` — only stages the new object in the session's pending
   state; nothing is sent to MySQL yet.
5. `db.commit()` — flushes that pending `INSERT` and commits the
   transaction. This is the moment MySQL actually assigns the
   auto-increment `id`.
6. `db.refresh(row)` — re-queries `row` from the database so `row.id`
   reflects the real generated value. Skip it and `row.id` could still
   be stale or `None`, since SQLAlchemy doesn't know the
   database-generated value without asking for it back.
7. Back in `main.py`, `crud.create_item(db, item)` returns the whole
   `ItemModel` object; the route itself reshapes just `row.id` and
   `row.value` into the plain dict FastAPI serializes to JSON — the
   same split between "database logic" and "HTTP response shape" as
   every route in this topic.
8. There's **no GET route yet**. Opening `http://127.0.0.1:8000/items`
   in a browser sends a GET, so you get `405 Method Not Allowed` — the
   path exists, that method doesn't. That's expected on this page.

## Test it with Thunder Client

Test the backend on its own before writing any React.

1. **Install once:** VS Code → Extensions (`Ctrl+Shift+X`) → search
   **Thunder Client** → Install. A ⚡ icon appears in the Activity Bar.
2. Start the backend:

   ```bash
   cd example/7/a
   uvicorn main:app --reload
   ```

3. ⚡ → **New Request**. Method **POST**, URL
   `http://127.0.0.1:8000/items`.
4. **Body** tab → **JSON** (not Text, not Form):

   ```json
   {
     "value": "first"
   }
   ```

5. **Send**. Expected: **`201 Created`** and

   ```json
   { "id": 1, "value": "first" }
   ```

   The `id` is whatever MySQL assigns next — `1` on an empty table,
   `2` for the next one, and so on.

| You see | Why | Fix |
|---|---|---|
| `422` — *"Input should be a valid dictionary or object"* | Body sent as Text/Form, or not valid JSON | Body → **JSON**, send `{"value": "..."}` with double quotes |
| `422` — *"Field required"* | The key isn't `value` | Use exactly `value` |
| `405 Method Not Allowed` | Wrong method, or the running app has no POST route | Check the method dropdown, and that `main.py` has `@app.post("/items")` |
| Connection refused | Backend not running | Start `uvicorn` first |

## Frontend

## Add, and show the message

```jsx title="src/App.js"
const [newValue, setNewValue] = useState('');
const [message, setMessage] = useState('');
const API_URL = 'http://localhost:8000'

async function addItem() {
  const response = await axios.post(`${API_URL}/items`, { value: newValue });
  setMessage(`Item added: ${response.data.value}`);
  setNewValue('');
}
```

```jsx
<input
  value={newValue}
  onChange={(e) => setNewValue(e.target.value)}
  placeholder="New item"
/>
<button onClick={addItem}>
  Add
</button>
{message && <p>{message}</p>}
```

The request is the same as [React's POST](/en/docs/react/post) — the
body is the same `{ value }` shape either way. **What's new is that the
page reads the response:** the backend sends back the saved row, and the
page turns it into a message.

## Line by line

1. **State** — no `items` list yet: just the input (`newValue`) and the
   `message`.
2. `API_URL = 'http://localhost:8000'` — where `uvicorn` is running.
3. `axios.post(...)` with `{ value: newValue }` — axios turns the object
   into JSON and sets `Content-Type: application/json`, the same body
   you sent from Thunder Client's JSON tab. Sending anything else (plain
   text like `` `value` = `first` ``) is what produces the `422`.
4. `response.data` is the backend's JSON response, so
   `response.data.value` is the value MySQL just saved. With no GET to
   refetch the list from, the page shows it as the message.
5. `setNewValue('')` clears the input after a successful add.
6. `{message && <p>{message}</p>}` renders the message only once there
   is one; each add replaces the previous message.
7. The button calls `addItem` directly with `onClick` — there's no
   `<form>`, so there's no page reload to prevent.
8. If the request fails (backend not running, CORS, `422`), axios
   throws and nothing on the page changes — open the browser console
   (F12) to see the error. The [GET](/en/docs/mysql-react/get) page's
   code adds a `try`/`catch` to show errors on the page.
9. Refresh the page and the message is gone, but the row is still in
   MySQL. [GET](/en/docs/mysql-react/get) loads it back.

**Running it:** this is a Create React App project (`npx
create-react-app`), started with `npm start` on
[http://localhost:3000](http://localhost:3000) — which is why `main.py`'s
CORS `allow_origins` includes `http://localhost:3000`. The same
`App.js` also works as `App.jsx` in the Vite app under
`example/7/react` (port `5173`).
