## The code

**`database.py`** — env vars, `engine`/`SessionLocal`/`Base`, and the
`get_db()` dependency:

```python title="database.py"
import os

from dotenv import load_dotenv
from sqlalchemy import create_engine
from sqlalchemy.orm import Session, declarative_base, sessionmaker

load_dotenv()

MYSQL_HOST = os.getenv("MYSQL_HOST", "127.0.0.1")
MYSQL_PORT = os.getenv("MYSQL_PORT", "3306")
MYSQL_USER = os.getenv("MYSQL_USER", "root")
MYSQL_PASSWORD = os.getenv("MYSQL_PASSWORD", "")
MYSQL_DB = os.getenv("MYSQL_DB", "fastapi_learn")

# Set DATABASE_URL directly to override everything above (e.g. to point
# at SQLite for a quick local test with no MySQL server at all).
DATABASE_URL = os.getenv(
    "DATABASE_URL",
    f"mysql+pymysql://{MYSQL_USER}:{MYSQL_PASSWORD}@{MYSQL_HOST}:{MYSQL_PORT}/{MYSQL_DB}",
)

engine = create_engine(DATABASE_URL, pool_pre_ping=True)
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)
Base = declarative_base()


def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

**`models.py`** — the `ItemModel` table:

```python title="models.py"
from sqlalchemy import Column, Integer, String

from database import Base


class ItemModel(Base):
    __tablename__ = "items"

    id = Column(Integer, primary_key=True, autoincrement=True)
    value = Column(String(255), nullable=False)
```

**`crud.py`** — plain functions that talk to the database, no HTTP:

```python title="crud.py"
from sqlalchemy.orm import Session

from models import ItemModel


def get_items(db: Session) -> list[ItemModel]:
    return db.query(ItemModel).order_by(ItemModel.id).all()


def get_item(db: Session, item_id: int) -> ItemModel | None:
    return db.get(ItemModel, item_id)


def seed_items(db: Session) -> None:
    if db.query(ItemModel).count() == 0:
        db.add_all([ItemModel(value="first"), ItemModel(value="second")])
        db.commit()
```

**`main.py`** — the `FastAPI()` app and the two routes:

```python title="main.py"
from fastapi import Depends, FastAPI, HTTPException
from sqlalchemy.orm import Session

import crud
from database import Base, SessionLocal, engine, get_db

Base.metadata.create_all(bind=engine)

with SessionLocal() as db:
    crud.seed_items(db)

app = FastAPI()


@app.get("/items")
def list_items(db: Session = Depends(get_db)):
    return [{"id": row.id, "value": row.value} for row in crud.get_items(db)]


@app.get("/items/{item_id}")
def get_item(item_id: int, db: Session = Depends(get_db)):
    row = crud.get_item(db, item_id)
    if row is None:
        raise HTTPException(status_code=404, detail="Item not found")
    return {"id": row.id, "value": row.value}
```

## Line by line

`database.py`'s connection/session setup and `models.py`'s `ItemModel`
table are the same shared pieces every page in this topic uses — the
same `items` table across every verb now, not five separate tables —
see the [index page](/en/docs/mysql-crud) for those explained line by
line. Below covers what's specific to `crud.py` and `main.py` on this
page.

**`crud.py`:**

1. `get_items(db)` — three chained steps, and nothing reaches MySQL
   until the last one:
   - `db.query(ItemModel)` builds a SELECT scoped to whatever table
     `ItemModel` maps to.
   - `.order_by(ItemModel.id)` adds `ORDER BY id`, so rows come back in
     a stable, predictable order — skip it and MySQL is free to return
     rows in any order it likes, which could shuffle between requests.
   - `.all()` is what actually executes the query and loads every
     matching row into memory as a list of `ItemModel` objects.
   - The function returns that list of ORM objects as-is — no dict
     reshaping happens here, since `crud.py` stays HTTP-agnostic.
2. `get_item(db, item_id)` — `db.get(ItemModel, item_id)` is
   SQLAlchemy's shortcut for "fetch by primary key." It returns the
   matching `ItemModel` object if a row with that ID exists, or plain
   `None` if it doesn't — it does **not** raise an exception on a
   miss, and `get_item` passes that `None` straight back to its
   caller rather than doing anything about it.

**`main.py`:**

3. `db: Session = Depends(get_db)` — FastAPI's dependency injection at
   work on both routes: FastAPI calls `get_db()` itself before either
   route body runs.
   - `get_db` is a generator function — notice the `yield` inside it —
     so FastAPI runs it up to that `yield`, and the value it yields (a
     fresh `SessionLocal()` instance) becomes whatever gets bound to
     the `db` parameter here.
   - Once the route returns (or raises), FastAPI resumes `get_db()`
     right after the `yield`, running its `finally: db.close()` — so
     the session always gets closed, success or failure, without
     either route needing its own `try`/`finally`.
   - Without `Depends`, every route would have to open and remember to
     close its own session by hand — and a forgotten `close()` after an
     exception quietly leaks a database connection.
4. `list_items(db)` — calls `crud.get_items(db)` and reshapes the
   result with `[{"id": row.id, "value": row.value} for row in ...]`,
   converting each ORM object into a plain dict — FastAPI's JSON
   encoder can serialize plain Python types, not an `ItemModel`
   instance directly. That reshaping is `main.py`'s job, not
   `crud.py`'s.
5. `get_item(item_id, db)` — calls `crud.get_item(db, item_id)` and is
   the only place that knows what a miss means over HTTP:
   - `if row is None: raise HTTPException(status_code=404, ...)` is
     what turns `crud.get_item`'s `None` into an actual HTTP
     `404 Not Found` response — the same `404`-if-missing pattern from
     every earlier topic.
   - Skip that check and go straight to `row.value` when `row` is
     `None`, and Python raises `AttributeError: 'NoneType' object has
     no attribute 'value'` instead — which FastAPI turns into a generic
     `500 Internal Server Error`, not the clean `404` a missing ID
     deserves. Keeping that check in `main.py` instead of `crud.py` is
     what keeps `crud.get_item` reusable anywhere, not just behind this
     one HTTP route.
