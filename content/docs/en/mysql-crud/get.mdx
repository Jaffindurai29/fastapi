## The code

```python title="main.py"
from fastapi import Depends, FastAPI, HTTPException
from sqlalchemy.orm import Session
# ...engine/Base/ItemModel/get_db from the setup on the index page

app = FastAPI()

@app.get("/items")
def list_items(db: Session = Depends(get_db)):
    rows = db.query(ItemModel).order_by(ItemModel.id).all()
    return [{"id": row.id, "value": row.value} for row in rows]

@app.get("/items/{item_id}")
def get_item(item_id: int, db: Session = Depends(get_db)):
    row = db.get(ItemModel, item_id)
    if row is None:
        raise HTTPException(status_code=404, detail="Item not found")
    return {"id": row.id, "value": row.value}
```

## Line by line

1. `db: Session = Depends(get_db)` — FastAPI calls `get_db()` before
   this route runs, opening a session, and closes it afterward
   automatically, even if the route raises an error.
2. `db.query(ItemModel).order_by(ItemModel.id).all()` — every row in
   the table, in a predictable order.
3. `db.get(ItemModel, item_id)` — SQLAlchemy's shortcut for "fetch by
   primary key." It returns the matching `ItemModel` object if a row
   with that ID exists, or plain `None` if it doesn't — it does **not**
   raise an exception on a miss.
   - `if row is None: raise HTTPException(status_code=404, ...)` is
     what turns that `None` into an actual HTTP `404 Not Found`
     response — the same `404`-if-missing pattern from every earlier
     topic.
   - Skip that check and go straight to `row.value` when `row` is
     `None`, and Python raises `AttributeError: 'NoneType' object has
     no attribute 'value'` instead — which FastAPI turns into a generic
     `500 Internal Server Error`, not the clean `404` a missing ID
     deserves.
