## The code

**`database.py`** — env vars, `engine`/`SessionLocal`/`Base`, and the
`get_db()` dependency:

```python title="database.py"
import os

from dotenv import load_dotenv
from sqlalchemy import create_engine
from sqlalchemy.orm import Session, declarative_base, sessionmaker

load_dotenv()

MYSQL_HOST = os.getenv("MYSQL_HOST", "127.0.0.1")
MYSQL_PORT = os.getenv("MYSQL_PORT", "3306")
MYSQL_USER = os.getenv("MYSQL_USER", "root")
MYSQL_PASSWORD = os.getenv("MYSQL_PASSWORD", "")
MYSQL_DB = os.getenv("MYSQL_DB", "fastapi_learn")

# Set DATABASE_URL directly to override everything above (e.g. to point
# at SQLite for a quick local test with no MySQL server at all).
DATABASE_URL = os.getenv(
    "DATABASE_URL",
    f"mysql+pymysql://{MYSQL_USER}:{MYSQL_PASSWORD}@{MYSQL_HOST}:{MYSQL_PORT}/{MYSQL_DB}",
)

engine = create_engine(DATABASE_URL, pool_pre_ping=True)
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)
Base = declarative_base()


def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

**`models.py`** — the `ItemModel` table:

```python title="models.py"
from sqlalchemy import Column, Integer, String

from database import Base


class ItemModel(Base):
    __tablename__ = "items"

    id = Column(Integer, primary_key=True, autoincrement=True)
    value = Column(String(255), nullable=False)
```

**`schemas.py`** — the request body `POST` needs:

```python title="schemas.py"
from pydantic import BaseModel


class ItemRequest(BaseModel):
    value: str
```

**`crud.py`** — plain functions that talk to the database, no HTTP:

```python title="crud.py"
from sqlalchemy.orm import Session

from models import ItemModel
from schemas import ItemRequest


def create_item(db: Session, item: ItemRequest) -> ItemModel:
    row = ItemModel(value=item.value)
    db.add(row)
    db.commit()
    db.refresh(row)
    return row


def seed_items(db: Session) -> None:
    if db.query(ItemModel).count() == 0:
        db.add_all([ItemModel(value="first"), ItemModel(value="second")])
        db.commit()
```

**`main.py`** — the `FastAPI()` app and the route:

```python title="main.py"
from fastapi import Depends, FastAPI, status
from sqlalchemy.orm import Session

import crud
from database import Base, SessionLocal, engine, get_db
from schemas import ItemRequest

Base.metadata.create_all(bind=engine)

with SessionLocal() as db:
    crud.seed_items(db)

app = FastAPI()


@app.post("/items", status_code=status.HTTP_201_CREATED)
def create_item(item: ItemRequest, db: Session = Depends(get_db)):
    row = crud.create_item(db, item)
    return {"id": row.id, "value": row.value}
```

## Line by line

`database.py`'s connection/session setup and `models.py`'s `ItemModel`
table are the same shared pieces every page in this topic uses — the
same `items` table across every verb now, not five separate tables —
see the [index page](/en/docs/mysql-crud) for those explained line by
line. Below covers what's specific to `schemas.py`, `crud.py`, and
`main.py` on this page.

**`schemas.py`:**

1. `ItemRequest(BaseModel)` — a required `value: str` field. FastAPI
   parses the request body into this model before the route ever runs,
   and rejects the request with `422 Unprocessable Entity` if `value`
   is missing or the wrong type — the route body never even starts.

**`crud.py`:**

2. `create_item(db, item)`:
   - `row = ItemModel(value=item.value)` — builds a new ORM object in
     memory; nothing is written to the database yet.
   - `db.add(row)` — only stages the new object in the session's
     pending state; nothing is sent to MySQL yet.
   - `db.commit()` — flushes that pending `INSERT` and commits the
     transaction. This is the moment MySQL actually assigns the
     auto-increment `id`.
   - `db.refresh(row)` — re-queries `row` from the database so
     `row.id` reflects the real generated value. Skip it and `row.id`
     could still be stale or `None`, since SQLAlchemy doesn't know the
     database-generated value without asking for it back.
   - `create_item` returns the ORM object itself, not a dict — shaping
     it into a response is left to whoever calls it. Keeping `crud.py`
     free of any HTTP-shaped return value is what makes it reusable
     from anywhere, not just this one route.

**`main.py`:**

3. `db: Session = Depends(get_db)` — same dependency injection as
   [GET](/en/docs/mysql-crud/get): FastAPI runs `get_db()` up to its
   `yield` before this route body executes, hands over the freshly
   created session as `db`, and closes that session automatically once
   this route finishes, success or failure.
4. `create_item(item, db)` — calls `crud.create_item(db, item)` and
   reshapes the returned `ItemModel` into `{"id": row.id, "value":
   row.value}` for the response. There's no miss to handle here — a
   `POST` always creates something — so unlike every other verb in
   this topic, this route has no `HTTPException` to raise.

