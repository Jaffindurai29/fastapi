## The code

```python title="main.py"
from fastapi import Depends, FastAPI, HTTPException, status
from sqlalchemy.orm import Session

app = FastAPI()

@app.delete("/items/{item_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_item(item_id: int, db: Session = Depends(get_db)):
    row = db.get(ItemModel, item_id)
    if row is None:
        raise HTTPException(status_code=404, detail="Item not found")
    db.delete(row)
    db.commit()
```

## Line by line

1. **Look the row up first** — `db.get(ItemModel, item_id)` returns the
   `ItemModel` object if that ID exists, or `None` if it doesn't.
   - `if row is None: raise HTTPException(status_code=404, ...)` sends
     back a clean `404` before `db.delete(row)` ever runs.
   - Skip that check and call `db.delete(None)` on a missing ID
     instead, and SQLAlchemy raises its own error rather than deleting
     anything — which FastAPI turns into a generic `500 Internal
     Server Error`, not the clean `404` a missing ID should produce.
2. **`db.delete(row)` then `db.commit()`** — stages the deletion, then
   writes it.
3. **Unlike the array topic**, deleting a row here never shifts any
   other row's `id` — MySQL's auto-increment `id` is a stable identity,
   not a position in a list. That's one of the real advantages of a
   database over an in-memory array for anything that needs to survive
   deletions predictably.

## Try it

```bash
curl -i -X DELETE http://127.0.0.1:8000/items/1
curl -i -X DELETE http://127.0.0.1:8000/items/999  # 404
```
