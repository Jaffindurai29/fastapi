## The code

**`database.py`** — env vars, `engine`/`SessionLocal`/`Base`, and the
`get_db()` dependency:

```python title="database.py"
import os

from dotenv import load_dotenv
from sqlalchemy import create_engine
from sqlalchemy.orm import Session, declarative_base, sessionmaker

load_dotenv()

MYSQL_HOST = os.getenv("MYSQL_HOST", "127.0.0.1")
MYSQL_PORT = os.getenv("MYSQL_PORT", "3306")
MYSQL_USER = os.getenv("MYSQL_USER", "root")
MYSQL_PASSWORD = os.getenv("MYSQL_PASSWORD", "")
MYSQL_DB = os.getenv("MYSQL_DB", "fastapi_learn")

# Set DATABASE_URL directly to override everything above (e.g. to point
# at SQLite for a quick local test with no MySQL server at all).
DATABASE_URL = os.getenv(
    "DATABASE_URL",
    f"mysql+pymysql://{MYSQL_USER}:{MYSQL_PASSWORD}@{MYSQL_HOST}:{MYSQL_PORT}/{MYSQL_DB}",
)

engine = create_engine(DATABASE_URL, pool_pre_ping=True)
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)
Base = declarative_base()


def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

**`models.py`** — the `ItemModel` table:

```python title="models.py"
from sqlalchemy import Column, Integer, String

from database import Base


class ItemModel(Base):
    __tablename__ = "items"

    id = Column(Integer, primary_key=True, autoincrement=True)
    value = Column(String(255), nullable=False)
```

**`schemas.py`** — the same request body [POST](/en/docs/mysql-crud/post) uses:

```python title="schemas.py"
from pydantic import BaseModel


class ItemRequest(BaseModel):
    value: str
```

**`crud.py`** — plain functions that talk to the database, no HTTP:

```python title="crud.py"
from sqlalchemy.orm import Session

from models import ItemModel
from schemas import ItemRequest


def get_item(db: Session, item_id: int) -> ItemModel | None:
    return db.get(ItemModel, item_id)


def replace_item(db: Session, item_id: int, item: ItemRequest) -> ItemModel | None:
    row = get_item(db, item_id)
    if row is None:
        return None
    row.value = item.value
    db.commit()
    db.refresh(row)
    return row


def seed_items(db: Session) -> None:
    if db.query(ItemModel).count() == 0:
        db.add_all([ItemModel(value="first"), ItemModel(value="second")])
        db.commit()
```

**`main.py`** — the `FastAPI()` app and the route:

```python title="main.py"
from fastapi import Depends, FastAPI, HTTPException
from sqlalchemy.orm import Session

import crud
from database import Base, SessionLocal, engine, get_db
from schemas import ItemRequest

Base.metadata.create_all(bind=engine)

with SessionLocal() as db:
    crud.seed_items(db)

app = FastAPI()


@app.put("/items/{item_id}")
def replace_item(item_id: int, item: ItemRequest, db: Session = Depends(get_db)):
    row = crud.replace_item(db, item_id, item)
    if row is None:
        raise HTTPException(status_code=404, detail="Item not found")
    return {"id": row.id, "value": row.value}
```

## Line by line

`database.py`'s connection/session setup and `models.py`'s `ItemModel`
table are the same shared pieces every page in this topic uses — the
same `items` table across every verb now — see the
[index page](/en/docs/mysql-crud) for those explained line by line.
`schemas.py`'s `ItemRequest` is the same one
[POST](/en/docs/mysql-crud/post) uses. Below covers what's specific to
`crud.py` and `main.py` on this page.

**`crud.py`:**

1. `get_item(db, item_id)` — `db.get(ItemModel, item_id)` is
   SQLAlchemy's fetch-by-primary-key shortcut: it returns the
   `ItemModel` object if that ID exists, or `None` if it doesn't,
   without raising an exception either way.
2. `replace_item(db, item_id, item)`:
   - **Looks the row up first**, via `get_item`, and if that comes
     back `None`, `replace_item` returns `None` right back rather than
     raising anything — `crud.py` never knows about HTTP status codes;
     turning a miss into an actual error is left to whoever calls it.
   - `row.value = item.value` looks like a plain attribute assignment
     because it is one — but since `row` came from `get_item` earlier
     in this same session, SQLAlchemy's "unit of work" is already
     tracking that object, so the change is picked up automatically.
     Nothing needs to be re-added to the session (no `db.add(row)`
     here) — that's the real difference from
     [POST](/en/docs/mysql-crud/post), where `row` is a brand-new
     object the session doesn't know about yet.
   - `db.commit()` is what turns that tracked in-memory change into an
     actual `UPDATE ... SET value = ... WHERE id = ...` statement sent
     to MySQL — nothing reaches the database before this line runs.
   - `db.refresh(row)` re-queries `row` from the database afterward,
     so the object this function returns reflects exactly what MySQL
     now has, rather than just echoing back the input the client
     already sent.

**`main.py`:**

3. `db: Session = Depends(get_db)` — same dependency injection as
   [GET](/en/docs/mysql-crud/get): FastAPI opens a fresh session via
   `get_db()` before this route runs and closes it automatically
   afterward, whether the route succeeds or raises.
4. `replace_item(item_id, item, db)` — calls `crud.replace_item(db,
   item_id, item)` and is the only place that turns a miss into an
   actual HTTP response:
   - `if row is None: raise HTTPException(status_code=404, ...)` turns
     `crud.replace_item`'s `None` into a clean `404 Not Found` before
     anything else runs.
   - Skip that check and go straight to `{"id": row.id, "value":
     row.value}` when `row` is `None`, and Python raises
     `AttributeError: 'NoneType' object has no attribute 'id'` instead
     — which FastAPI turns into a generic `500 Internal Server Error`
     instead of the `404` a missing ID should produce. Keeping that
     check in `main.py` instead of `crud.py` is what keeps
     `crud.replace_item` reusable anywhere, not just behind this one
     HTTP route.

## Try it

```bash
curl -X PUT http://127.0.0.1:8000/items/1 -H "Content-Type: application/json" -d "{\"value\": \"replaced\"}"
curl -i -X PUT http://127.0.0.1:8000/items/999 -H "Content-Type: application/json" -d "{\"value\": \"x\"}"  # 404
```
