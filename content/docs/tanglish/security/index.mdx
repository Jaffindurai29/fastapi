## Hashing vs encryption vs encoding/signing

Easy-a kozhappikka koodiya moonu vera vera tools:

| | Reversible-a? | Key venumaa? | Edhukku use pannanum | Indha topic-la |
|---|---|---|---|---|
| **Hashing** | Illa, one-way. "Indha input match aagudha?" nu mattum dhan check panna mudiyum | Illa (salt hash-kulleye store aagum) | Passwords. Adha thirumba read panna thevai illa, verify panna mattum podhum. | [Password hashing](/tanglish/docs/security/password-hashing), pwdlib / Argon2 |
| **Encryption** | Aamaa, two-way, key-oda | Aamaa, key yaar kitta irukko avanga decrypt pannalaam | Thirumba read panna vendiya sensitive data (phone numbers, unga users-oda API keys, ...) | [Encrypt/decrypt fields](/tanglish/docs/security/encryption), Fernet |
| **Encoding + signing (JWT)** | Aamaa, **yaar venumnaalum**. Payload verum base64 dhan. | Key **sign** mattum dhan pannum. Token tamper aagalai-nu prove pannum. | Oruthar yaaru-nu (`sub`) forge panna mudiyaadha maadhiri solradhu | [JWT login](/tanglish/docs/security/jwt-login), PyJWT HS256 |

Idhula irundhu vara practical rules:

- **Passwords-ah eppovum encrypt pannadheenga. Hash pannunga.**
  Passwords encrypt pannirundha, key-ah thirudravanga (illa server-e)
  ella password-aiyum thirumba plain text-a maathidalaam. Hash-la
  thirumba maathradhukku edhuvum illa: server kooda oru guess-ah check
  mattum dhan panna mudiyum.
- **JWT-kulla secrets podadheenga.** Token kaila irukra yaar venumnaalum
  adha read pannalaam. Oru token-ah [jwt.io](https://jwt.io)-la paste
  panni neengale paarunga.
- **sqids ([ID hashing](/tanglish/docs/security/id-hashing)) encoding,
  security illa.** Id-oda shape-ah hide pannum, aana real protection
  innum [ownership check](/tanglish/docs/security/ownership) dhan.

## Setup

[MySQL + CRUD](/tanglish/docs/mysql-crud)-oda same database setup dhan
(`fastapi_learn` database, `MYSQL_*` variables illana `.env`, illana
SQLite fallback). Indha topic-ku pudhusa vara packages:

```bash
pip install "pwdlib[argon2]" pyjwt cryptography sqids slowapi python-multipart
```

| Package | Edhukku |
|---|---|
| `pwdlib[argon2]` | Argon2 vachi password hashing (`passlib`-oda modern replacement) |
| `pyjwt` | JSON Web Tokens create panni verify panradhu |
| `cryptography` | sensitive columns-ku Fernet encryption |
| `sqids` | short, non-sequential public ids |
| `slowapi` | rate limiting |
| `python-multipart` | login route ethirpaakra **form**-ah FastAPI read panna |

Tokens irukra letters `SECRET_KEY`, `ACCESS_TOKEN_EXPIRE_MINUTES`,
`REFRESH_TOKEN_EXPIRE_DAYS`-ah environment-la irundhu read pannum
(ovoru folder-oda `.env.example` paarunga). Ellathukkum working
development defaults irukku, so laptop-la skip pannalaam. Real-a edhavadhu
pannumbodhu, oru key generate pannunga:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

## Login eppadi work aagudhu (12/b-la irundhu)

[JWT login](/tanglish/docs/security/jwt-login)-la irundhu, login na
**form fields**-oda `POST /token`, JSON illa. OAuth2 "password flow"
standard adha dhan solludhu, `/docs` page-kum adha dhan anuppa
theriyum. curl-la, `Content-Type` header illama `-d` kudutha adhu oru
form anuppum:

```bash
curl -X POST http://127.0.0.1:8000/token -d "username=alice&password=alice-password"
```

Answer oru token:

```json
{"access_token": "eyJhbGciOiJIUzI1NiIs...", "token_type": "bearer"}
```

`access_token`-ah copy panni, ovoru protected request-layum
`Authorization` header-la anuppunga:

```bash
curl http://127.0.0.1:8000/users/me -H "Authorization: Bearer <paste token>"
```

**`/docs`-la:** **Authorize** button-ah click pannunga (top right),
`alice` / `alice-password` type pannunga, ippo lock aana ovoru route-um
(padlock-oda kaattum) unga-ku token-ah automatic-a anuppum. Adhe
dialog-la **Logout** pannina token pogum, `401`-gala paakalaam.

**Postman-la:** Body → x-www-form-urlencoded-la (`username`,
`password`; JSON anuppina `422`) login pannunga, apparam protected
request-la **Authorization** tab → **Bearer Token** open panni token-ah
paste pannunga.

## 401 vs 403 — rendu "no" answers

Kittathatta ella page-layum rendaiyum paapeenga, so rule-ah oru thadava
solliduvom:

| Status | Name | Real meaning | Fix |
|---|---|---|---|
| `401` | Unauthorized | "Neenga yaaru-nu theriyala" — token illa, bad token, expired token, wrong password | Thirumba login pannunga |
| `403` | Forbidden | "Neenga yaaru-nu nalla theriyum, aana mudiyaadhu" — wrong role, unga row illa, deactivated account | Thirumba login pannaalum help aagadhu |
