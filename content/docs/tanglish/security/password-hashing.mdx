Tokens varradhukku munnadi, passwords-ah **safe-a** store panradhu.
`POST /register` password-ah Argon2 vachi hash panni, hash-ah mattum
dhan store pannum. `POST /login` oru password-ah andha hash-oda check
pannum. `GET /hash-demo` same password-ah rendu thadava hash pannum —
rendu results-um vera vera, aana rendum verify aagum-nu neengale
paakalaam.

| Route | Description |
|---|---|
| `POST /register` | User create pannum; `201`, username already irundha `409`, username 3–30 chars illana illa password 8-ku keezha irundha `422` |
| `POST /login` | Username + password (JSON) check pannum; `200` illana `401 Incorrect username or password` |
| `GET /users` | Ella users-um: `id`, `username` mattum, hash eppovum illa |
| `GET /hash-demo?password=secret` | Oru password-ah rendu thadava hash pannum; rendu vera vera hashes, rendum verify aagum |

Table: `sec_a_users`, `alice` / `alice-password`, `bob` /
`bob-password`, `admin` / `admin-password`-oda seed aagum.

## Code

**`database.py`** — env vars, `engine`/`SessionLocal`/`Base`, mattrum
`get_db()` dependency (topic 6-oda same):

```python title="database.py"
import os

from dotenv import load_dotenv
from sqlalchemy import create_engine
from sqlalchemy.orm import Session, declarative_base, sessionmaker

load_dotenv()

MYSQL_HOST = os.getenv("MYSQL_HOST", "127.0.0.1")
MYSQL_PORT = os.getenv("MYSQL_PORT", "3306")
MYSQL_USER = os.getenv("MYSQL_USER", "root")
MYSQL_PASSWORD = os.getenv("MYSQL_PASSWORD", "")
MYSQL_DB = os.getenv("MYSQL_DB", "fastapi_learn")

# Set DATABASE_URL directly to override everything above (e.g. to point
# at SQLite for a quick local test with no MySQL server at all).
DATABASE_URL = os.getenv(
    "DATABASE_URL",
    f"mysql+pymysql://{MYSQL_USER}:{MYSQL_PASSWORD}@{MYSQL_HOST}:{MYSQL_PORT}/{MYSQL_DB}",
)

engine = create_engine(DATABASE_URL, pool_pre_ping=True)
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)
Base = declarative_base()


def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

**`models.py`** — users table, hash column irukku, password column
illa:

```python title="models.py"
from sqlalchemy import Column, Integer, String

from database import Base


class UserModel(Base):
    __tablename__ = "sec_a_users"

    id = Column(Integer, primary_key=True, autoincrement=True)
    username = Column(String(30), nullable=False, unique=True)
    # Only the HASH is stored. There is no "password" column at all.
    # 255 leaves room: an Argon2 hash is ~97 characters.
    hashed_password = Column(String(255), nullable=False)
```

**`schemas.py`** — ulla varradhu (plain password) mattrum veliya
pogradhu (password-um illa, hash-um illa):

```python title="schemas.py"
from pydantic import BaseModel, ConfigDict, Field


# What the client sends to /register: a plain-text password, over HTTPS.
class UserCreate(BaseModel):
    username: str = Field(min_length=3, max_length=30)
    password: str = Field(min_length=8, max_length=128)


class LoginRequest(BaseModel):
    username: str
    password: str


# What goes back out. No password, no hash: response_model drops
# hashed_password even though the route returns the full row.
class UserOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: int
    username: str
```

**`security.py`** — hashing mattrum verifying, vera onnum illa:

```python title="security.py"
from pwdlib import PasswordHash

# Argon2 with sensible defaults. (passlib, used in older tutorials,
# no longer works on Python 3.13+; pwdlib is its modern replacement.)
password_hash = PasswordHash.recommended()


def hash_password(password: str) -> str:
    # One-way: a fresh random salt is mixed in every call, so the same
    # password gives a different hash each time.
    return password_hash.hash(password)


def verify_password(password: str, hashed: str) -> bool:
    # Re-hashes the attempt using the salt stored inside `hashed` and
    # compares. The original password is never recovered.
    return password_hash.verify(password, hashed)
```

**`crud.py`** — ulla varumbodhu hash, login-la verify:

```python title="crud.py"
from sqlalchemy.orm import Session

from models import UserModel
from security import hash_password, verify_password


def get_users(db: Session) -> list[UserModel]:
    return db.query(UserModel).order_by(UserModel.id).all()


def get_user_by_username(db: Session, username: str) -> UserModel | None:
    return db.query(UserModel).filter(UserModel.username == username).first()


def create_user(db: Session, username: str, password: str) -> UserModel:
    # Hash BEFORE it touches the database. The plain password is
    # never stored, logged, or returned.
    row = UserModel(username=username, hashed_password=hash_password(password))
    db.add(row)
    db.commit()
    db.refresh(row)
    return row


def authenticate(db: Session, username: str, password: str) -> UserModel | None:
    user = get_user_by_username(db, username)
    if user is None:
        return None
    if not verify_password(password, user.hashed_password):
        return None
    return user


def seed_users(db: Session) -> None:
    if db.query(UserModel).count() == 0:
        for name in ("alice", "bob", "admin"):
            db.add(UserModel(username=name, hashed_password=hash_password(f"{name}-password")))
        db.commit()
```

**`main.py`** — app mattrum adhoda naalu routes:

```python title="main.py"
from fastapi import Depends, FastAPI, HTTPException, status
from sqlalchemy.orm import Session

import crud
from database import Base, SessionLocal, engine, get_db
from schemas import LoginRequest, UserCreate, UserOut
from security import hash_password, verify_password

Base.metadata.create_all(bind=engine)

with SessionLocal() as db:
    crud.seed_users(db)

app = FastAPI()


@app.post("/register", response_model=UserOut, status_code=status.HTTP_201_CREATED,
          responses={409: {"description": "Username already taken"}})
def register(user: UserCreate, db: Session = Depends(get_db)):
    if crud.get_user_by_username(db, user.username) is not None:
        raise HTTPException(status_code=409, detail="Username already taken")
    return crud.create_user(db, user.username, user.password)


@app.post("/login", responses={401: {"description": "Incorrect username or password"}})
def login(body: LoginRequest, db: Session = Depends(get_db)):
    user = crud.authenticate(db, body.username, body.password)
    if user is None:
        # Same message for "no such user" and "wrong password", so an
        # attacker can't use this route to discover which usernames exist.
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Incorrect username or password",
            headers={"WWW-Authenticate": "Bearer"},
        )
    # No token yet: the client learns "yes, that's right" and nothing more.
    # 12/b turns this into a JWT the client can send on later requests.
    return {"message": "Login successful", "username": user.username}


@app.get("/users", response_model=list[UserOut])
def list_users(db: Session = Depends(get_db)):
    return crud.get_users(db)


# Teaching route: hash the same password twice to show the salt at work.
# (Never put a real password in a URL; it ends up in server logs.)
@app.get("/hash-demo")
def hash_demo(password: str = "secret"):
    first = hash_password(password)
    second = hash_password(password)
    return {
        "password": password,
        "hash_1": first,
        "hash_2": second,
        "hashes_equal": first == second,
        "verify_hash_1": verify_password(password, first),
        "verify_hash_2": verify_password(password, second),
        "verify_wrong_password": verify_password(password + "x", first),
    }
```

## Line by line

`database.py` [MySQL + CRUD](/tanglish/docs/mysql-crud)-la irukra adhe
dhan. Indha page-oda pudhu idea: **server-aala kooda oru user-oda
password-ah read panna mudiya koodadhu — adhu store panni vachirukra
copy-ah kooda.**

**Hashing, idea:**

1. **Hashing encryption illa.** Encryption two-way: key irundha
   original thirumba kidaikkum. Hash **one-way**: `"alice-password"`-ah
   hash-a maathalaam, aana hash-ah thirumba `"alice-password"`-a
   maathra edhuvum illa. Adha "decrypt" panna mudiyaadhu. Login check
   panna, attempt-ah same maadhiri hash panni compare pannuvom.
   Database leak aana, attacker-ku hashes dhan kidaikkum, passwords
   illa — ovoru password-aiyum onnu onna guess pannanum.
2. **Appo yen passwords-ah encrypt pannakoodadhu?** Encryption-ku oru
   key venum, andha key server-la enga-yavadhu irundhaaganum. Database
   *mattrum* key rendum yaar kaila kidaichaalum (attacker, careless
   backup, curious employee) ella password-aiyum oru shot-la decrypt
   pannidalaam. Password-ah thirumba read panna thevaiye illa — "idhu
   correct-a?" nu mattum answer pannaa podhum — so one-way hash-la
   namakku venum ellam irukku, attacker reverse panna edhuvum illa.
3. **Plain text eppovum store pannadheenga.** Makkal passwords-ah reuse
   pannuvaanga. Plain-text passwords table leak aana, adhu email mattrum
   bank logins-um leak aanadhu maadhiri dhan.

**`models.py`:**

4. `hashed_password = Column(String(255), nullable=False)` — `password`
   column-e illa. Oru Argon2 hash kitta thatta 97 characters; 255 room
   vidum. `username` `unique=True`, same name-la rendu users varaama
   database-oda last line of defence.

**`security.py`:**

5. `PasswordHash.recommended()` — pwdlib safe settings-oda Argon2-ah
   pick pannum. Pazhaya FastAPI tutorials `passlib` + bcrypt use
   pannuvaanga; `passlib` ippo maintain aagala, Python 3.13+-la break
   aagudhu, so `pwdlib` use pannunga.
6. **Yen slow algorithm, SHA-256 illa.** SHA-256 **fast**-a irukka
   build pannadhu: oru graphics card oru SHA-256 hash-ku against-a
   second-ku billions of guesses try pannum. Argon2 (mattrum bcrypt)
   purposely **slow-a, memory-hungry-a** irukka build pannadhu. Oru
   login second-oda oru siriya part dhan edukkum, yaarum notice panna
   maattaanga, aana billions of guesses practical-a mudiyaadhu. Cost
   settings hash-kulleye store aagum:

   ```
   $argon2id$v=19$m=65536,t=3,p=4$<salt>$<hash>
   ```

   `argon2id` variant, `m=65536` na ovoru hash-kum 64 MB memory, `t=3`
   na moonu passes, `p=4` na naalu parallel lanes. Appuram idha
   increase pannalaam, pazhaya hashes innum verify aagum — yen-na ovoru
   hash-um adhoda sontha settings-ah carry pannudhu.
7. **`hash_password` mattrum salt.** `hash()` call aagura ovoru
   thadavayum oru pudhu random **salt** mix aagum (kadaisi `$`-ku
   munnadi irukra chunk), adhu result-kulleye store aagum. Adhanaala
   dhan same password ovoru thadavayum vera hash kudukkudhu. Salt
   illana, `123456` password vachirukra ella users-kum same hash
   irukkum — onna crack pannina ellathaiyum crack pannina maadhiri, plus
   attackers pre-computed lookup tables ("rainbow tables") use
   pannalaam. Salt irundha, ovoru hash-aiyum thani-thaniya attack
   pannanum.
8. **`verify_password`** — stored hash-la irundhu salt mattrum
   settings-ah thirumba read panni, attempt-ah same maadhiri hash panni
   compare pannum. Salt-ah thaniya store panna thevai illa, original
   password eppovum thirumba kidaikkaadhu.

**`schemas.py`:**

9. `UserCreate` — password-la `Field(min_length=8, max_length=128)`,
   username-ku 3–30 characters. Romba chinna password route run
   aaguradhukku munnadiye `422`. Plain password inga oru thadava mattum
   varum (real life-la HTTPS-la), neraa `hash_password`-ku pogum.
10. `UserOut` — `id`, `username` mattum. `/register` mattrum `/users`
    `response_model=UserOut` use pannudhu, so routes full `UserModel`
    row return pannaalum, `hashed_password` veliya pogumbodhu drop
    aagidum. Hash password illa dhan, aana attacker offline-a crack
    panna exact-a adha dhan venum, so adhu database-laye irukkum.

**`crud.py`:**

11. `create_user` — database-ah edhuvum touch panradhukku **munnadi**
    `hash_password(password)` call pannum. Plain password eppovum store,
    log, illa return aagadhu.
12. `authenticate` — **rendu** failures-kum `None` return pannum: "andha
    user illa" mattrum "wrong password". Edhu-nu caller-ku solladhu.
13. `seed_users` — table empty-a irundha mattum run aagum,
    `hash_password(f"{name}-password")` store pannum, so demo users-kum
    real hashes dhan.

**`main.py`:**

14. `register` — first username-ah check panni `409 Username already
    taken` sollum, [Validation & Errors](/tanglish/docs/validation)-la
    duplicate names-ku paartha same pattern. Rendu requests race
    pannina `unique=True` column backup.
15. `login` — rendu failures-kum same message-oda oru `401`,
    `"Incorrect username or password"`. Oru case-la "user not found",
    innoru case-la "wrong password" nu sonna, yaar venumnaalum endha
    usernames irukku-nu kandupidikkalaam (**user enumeration**), apparam
    andha usernames-la mattum guess pannuvaanga.
    `headers={"WWW-Authenticate": "Bearer"}` — `401`-la HTTP spec
    ethirpaakradhu; adutha page-la tokens vandha appuram idhu matter
    aagum. (Porumaiyaana attacker rendu cases-oda timing-ah innum
    measure pannalaam, yen-na missing user slow `verify`-ah skip
    pannudhu. Sila production code adha sari panna oru dummy hash-ku
    against-a verify pannum.)
16. `hash_demo` — oru teaching route, same password-ah rendu thadava
    hash pannum: `hashes_equal` `false`, aana `verify_hash_1`,
    `verify_hash_2` rendum `true`, `verify_wrong_password` `false`.
    (Real password-ah eppovum URL-la podadheenga; URLs server logs-la
    pogum.)
17. **Enna missing: logged in-a irukradhu.** `/login` "aamaa, correct"
    nu mattum dhan sollum. Adutha request-ku adhu pathi onnum theriyaadhu,
    so client ovoru thadavayum password anuppanum. Adutha page success
    message-ku pathila oru signed token kudukkum.

## Try it

```bash
curl -X POST http://127.0.0.1:8000/register -H "Content-Type: application/json" -d "{\"username\": \"carol\", \"password\": \"carol-password\"}"
curl -X POST http://127.0.0.1:8000/login -H "Content-Type: application/json" -d "{\"username\": \"carol\", \"password\": \"carol-password\"}"
curl -i -X POST http://127.0.0.1:8000/login -H "Content-Type: application/json" -d "{\"username\": \"carol\", \"password\": \"wrong\"}"  # 401
curl http://127.0.0.1:8000/users
curl "http://127.0.0.1:8000/hash-demo?password=secret"
```
