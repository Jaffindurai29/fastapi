[Array + CRUD](/tanglish/docs/array-crud)-la irundha same aaru
verbs — same routes, same request/response shapes — aana Python
list-ku pathila real [MySQL](https://www.mysql.com/) table-ah
[SQLAlchemy](https://www.sqlalchemy.org/) moola read/write pannudhu.
Data restart aana survive aagum; array positions real, stable database
IDs-a maarum.

## Oru folder-la five files

Ovoru letter-oda code-um (`example/6/a` mudhal `example/6/e`
varaikkum) oru flat `main.py`-ku pathila layers-a split pannirukku:

| File | Responsibility |
|---|---|
| `database.py` | env vars, `engine`, `SessionLocal`, `Base`, `get_db()` |
| `models.py` | `ItemModel` — SQLAlchemy table |
| `schemas.py` | Pydantic request body — verb-ku body venumna mattum irukkum (GET, DELETE-ku skip) |
| `crud.py` | database-oda pesura plain functions, HTTP edhuvum theriyaadhu |
| `main.py` | `FastAPI()` app mattrum adhoda route(s) |

`database.py` mattrum `models.py` aaru folder-layum exact same-a
irukku — keezha irukra "Keezha irukra ovoru page-um share panra
pieces"-la adha line-by-line paarunga. Ovoru verb page-um adhoda
sontha `crud.py`/`main.py` split-ah full-a explain pannum.

Aaru folder-um (`6/a`-la irundhu `6/e` varaikkum) same `items`
table-ah dhan point pannudhu (five thani tables illa), so same
database-ku run pannina state share aagum — vera lesson-ah already
same database-ku run pannirundheenga na, specific id refer panra
`curl`/Postman example try pannradhukku munnadi `GET /items` run panni
enna ids ippo irukku-nu paarunga.

## Setup

```bash
pip install sqlalchemy pymysql python-dotenv
```

Indha database-ah once dhan create pannunga, MySQL client-la:

```sql
CREATE DATABASE fastapi_learn;
```

Apparam connection details-ah environment variables vachi set pannunga:

```bash
export MYSQL_HOST=127.0.0.1
export MYSQL_PORT=3306
export MYSQL_USER=root
export MYSQL_PASSWORD=your-password
export MYSQL_DB=fastapi_learn
```

...illana `.env.example`-ah `.env`-ku copy panni adhula edit pannunga —
rendu vazhi-um work aagum, `database.py` `.env`-ah automatic-a load
pannudhu-nala. Rendaiyum skip panna kuda problem illa: mela irukra
defaults (`root`, password illama, `127.0.0.1`-la) already code-la
baked-in irukku.

```bash
cp .env.example .env
```

MySQL kaiyila illaya? `DATABASE_URL`-ah SQLite file-ku pathila podunga —
same code maathama work aagum:

```bash
export DATABASE_URL="sqlite:///./test.db"
```

## Keezha irukra ovoru page-um share panra pieces

Indha moonu pieces `database.py` mattrum `models.py`-la dhan irukku,
`6/a` mudhal `6/e` varaikkum ella folder-layum exact same-a.

**Connection, environment variables-la irundhu (`database.py`-la):**

```python
DATABASE_URL = os.getenv(
    "DATABASE_URL",
    f"mysql+pymysql://{MYSQL_USER}:{MYSQL_PASSWORD}@{MYSQL_HOST}:{MYSQL_PORT}/{MYSQL_DB}",
)
engine = create_engine(DATABASE_URL, pool_pre_ping=True)
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)
```

## Line by line: connection (database.py-la)

1. `os.getenv("DATABASE_URL", f"mysql+pymysql://...")` — `DATABASE_URL`
   environment variable set-a irundha adha read pannum (mela irukra
   SQLite override maadhiri), illa-na individual `MYSQL_*`
   variables-la irundhu MySQL connection string build pannum.
   `mysql+pymysql://` nu solradhu, SQLAlchemy MySQL-oda pesa yentha
   driver — `pymysql` — use pannanum-nu therivikkudhu.
2. `create_engine(DATABASE_URL, pool_pre_ping=True)` — `engine`
   nu solradhu indha database-ku SQLAlchemy-oda connection factory;
   odane connect aagadhu, oru session real-a venumnu kekkumbodhu dhan
   connect aagum. `pool_pre_ping=True` vachu, pool-la irukra oru
   connection-ah reuse panna munnadi light-a ping pannum, so MySQL
   silent-a drop pannitta connection (idle-a irundhu) replace aagum,
   apparam confusing error varadhu.
3. `sessionmaker(autocommit=False, autoflush=False, bind=engine)` —
   indha engine-oda bind aana `Session` objects create panna oru
   factory. `autocommit=False` na, neenga explicit-a `db.commit()`
   call pannalaam varaikkum edhuvum database-ku write aagadhu;
   `autoflush=False` na, pending changes ovoru query-kum munnadi
   silent-a database-ku poogadhu, flush illa commit pannumbodhu
   mattum dhan — rendum sethu, exact-a eppo SQL run aagum-nu ovoru
   route-um full control vachurukkum.

**Table, Python class-a (`models.py`-la)** — real, stable,
auto-incrementing `id`-oda, array topic-oda position-based index illa:

```python
class ItemModel(Base):
    __tablename__ = "items"
    id = Column(Integer, primary_key=True, autoincrement=True)
    value = Column(String(255), nullable=False)

Base.metadata.create_all(bind=engine)
```

## Line by line: table (models.py-la)

1. `class ItemModel(Base):` — oru ORM model declare pannudhu. `Base`-la
   irundhu inherit pannuradhu dhan (SQLAlchemy-oda declarative base)
   indha class-ah plain Python class-a irukradhukku pathila, real
   database table-ku map panna vaikkudhu.
2. `__tablename__ = "items"` — MySQL-la create aagra actual table
   name.
3. `id = Column(Integer, primary_key=True, autoincrement=True)` —
   real, stable, auto-incrementing integer primary key, ovoru
   insert-um MySQL-ah dhan assign pannum.
4. `value = Column(String(255), nullable=False)` — required
   `VARCHAR(255)` column; `nullable=False` na, idha leave out panni
   insert pannina MySQL reject pannidum.
5. `Base.metadata.create_all(bind=engine)` — `Base`-la irundhu
   inherit panra ovoru model-kum, table already illainaa create
   pannum. App start aaguna ovoru thadavayum call panna safe —
   table already irundha idhu no-op.

**Ovoru request-kum oru session, `Depends` vachi (`database.py`-la)** —
munnadi topics-la paartha same dependency-injection pattern dhan, ippo
real database connection manage pannudhu:

```python
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

## Line by line: dependency (database.py-la)

1. `db = SessionLocal()` — oru pudhu database session open pannum.
2. `yield db` — andha session-ah `db: Session = Depends(get_db)` nu
   declare panna edhavadhu route-kum kudukkum; andha route function
   mudiyara varaikkum execution inga pause aagum.
3. `finally: db.close()` — route return aana appuram illa raise aana
   appuram run aagum, so session (adhoda connection) eppovum pool-ku
   thirumba release aagum, success-a irundhalum fail aana.

## Indha topic-la irukra pages

1. [GET](/tanglish/docs/mysql-crud/get) — ovoru row-um list pannunga, illana ID vachi oru row-ah reach pannunga.
2. [POST](/tanglish/docs/mysql-crud/post) — pudhu row insert pannunga.
3. [PUT](/tanglish/docs/mysql-crud/put) — oru row-oda value-ah full-a replace pannunga.
4. [PATCH](/tanglish/docs/mysql-crud/patch) — oru row-ah partially update pannunga.
5. [DELETE](/tanglish/docs/mysql-crud/delete) — ID vachi oru row-ah remove pannunga.
