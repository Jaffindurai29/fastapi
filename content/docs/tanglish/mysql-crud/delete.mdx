## Code

```python title="main.py"
from fastapi import Depends, FastAPI, HTTPException, status
from sqlalchemy.orm import Session

app = FastAPI()

@app.delete("/items/{item_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_item(item_id: int, db: Session = Depends(get_db)):
    row = db.get(ItemModel, item_id)
    if row is None:
        raise HTTPException(status_code=404, detail="Item not found")
    db.delete(row)
    db.commit()
```

## Line by line

1. **Row-ah first-a look up pannunga** — `db.get(ItemModel, item_id)`
   andha ID irundha `ItemModel` object return pannum, illa-na `None`
   return pannum.
   - `if row is None: raise HTTPException(status_code=404, ...)`
     `db.delete(row)` run aaguradhukku munnadi clean `404`-ah anuppum.
   - Idha check pannama `db.delete(None)`-ah call pannina, SQLAlchemy
     adhoda sontha error-ah raise pannum, edhuvum delete pannama —
     adha FastAPI generic `500 Internal Server Error`-a maathidum,
     missing ID-ku venum clean `404`-ku pathila.
2. **`db.delete(row)` apparam `db.commit()`** — deletion-ah stage
   pannum, apparam write pannum.
3. **Array topic-ku vidhyasam-a**, inga oru row-ah delete panna, vera
   edhavadhu row-oda `id` shift aagadhu — MySQL-oda auto-increment `id`
   oru stable identity dhan, list-la position illa. Deletions-ah
   predictable-a survive panna, in-memory array-ku vida database-oda
   real advantage idhu dhan.
