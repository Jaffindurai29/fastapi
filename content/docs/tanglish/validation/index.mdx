[MySQL + CRUD](/tanglish/docs/mysql-crud) client enna anuppinaalum
nambichu, eppovum `404` mattum dhan answer pannuchu. Indha topic API-ah:

- **ulla varradhula strict-a** aakkudhu — ovoru field-kum validation
  rules, so thappana input route run aaguradhukku munnadiye reject
  aagidum;
- **thappa pona correct-a solla** vaikkudhu — ovoru failure-kum
  sariyaana status code, mattrum ellathukkum oru consistent error shape;
- **yentha fields server-ah vittu veliya pogudhu-nu careful-a**
  aakkudhu — internal columns-ah ovoru response-la irundhum filter
  panra oru `response_model`.

Item-ku ippo oru field-ku pathila moonu fields irukku, so validate
panna real-a edhavadhu irukku: `name` (unique), `price`, mattrum
`quantity`.

## Yentha status code eppo?

Indha topic-la irundhu nyabagam vachukka vendiya oru table.
[8/b](/tanglish/docs/validation/status-codes) idhula ovvonnaiyum
purpose-a use pannudhu (`500` thavira):

| Code | Meaning | Inga example |
|---|---|---|
| `400 Bad Request` | Request well-formed dhan, aana artham illa | `PATCH` with `{}` — valid JSON, aana edhuvum kekkala |
| `404 Not Found` | URL-la irukra thing exist aagala | `GET /items/999` |
| `409 Conflict` | Valid request, aana stored data-oda clash aagudhu | duplicate name; innum stock-la irukra item-ah delete panradhu |
| `422 Unprocessable Content` | Body illa parameter oru validation rule-ah break pannuchu | `price: -1`, `/items/abc` — FastAPI idha unga-ku anuppidum |
| `500 Internal Server Error` | Unga code crash aachu | purpose-a eppovum anuppadheenga — idhu bug-nu artham |

Seekiram choose panna oru vazhi: request-ah mattum paathu thappu-nu
Pydantic-ku theriyum-na, adhu `422` (FastAPI adha unga-ku pannidum).
Thappu-nu theriya database venum-na, adhu `404` (illa) illana `409`
(irukradhoda clash). Valid aana artham illana, adhu `400`.

## Keezha irukra ovoru page-um share panra pieces

`database.py` naalu folder-layum exact same — topic 6-oda adhe dhan.
Adha line-by-line paakka [MySQL + CRUD index](/tanglish/docs/mysql-crud)
paarunga.

**Table (`models.py`-la, 8/a–8/c):**

```python
class ItemModel(Base):
    __tablename__ = "validation_items"

    id = Column(Integer, primary_key=True, autoincrement=True)
    name = Column(String(50), nullable=False, unique=True)
    price = Column(Float, nullable=False)
    quantity = Column(Integer, nullable=False, default=0)
```

## Line by line: table (models.py-la)

1. `__tablename__ = "validation_items"` — oru pudhu table, so indha
   topic topic 6-oda single-column `items` table-oda collide aagadhu.
2. `id = Column(Integer, primary_key=True, autoincrement=True)` —
   munnadi maadhiriye same auto-incrementing primary key.
3. `name = Column(String(50), nullable=False, unique=True)` — max 50
   characters, required, mattrum **unique**: database-e oru rendavadhu
   "Laptop"-ah refuse pannidum. Idhu dhan last line of defence; adhu
   *mattum dhan* defence-a irundha enna aagum-nu 8/a kaattudhu (oru
   `500`), 8/b adhukku munnadi oru proper check add pannudhu.
4. `price = Column(Float, nullable=False)` — required decimal number.
5. `quantity = Column(Integer, nullable=False, default=0)` — required
   whole number; insert-la idha vittuttaa SQLAlchemy `0` pottudum.

Column rules-um Pydantic rules-um purpose-a overlap aagudhu-nu
gavaninga: table-la `String(50)` schema-la `max_length=50`-oda match
aagudhu. Schema thappana input-ah polite-a `422`-oda reject pannum;
edhavadhu thappi ulla pona, column dhan safety net.

8/d-oda `models.py` idhe dhan plus rendu columns — adhu
[response_model page](/tanglish/docs/validation/response-model)-la
cover aagudhu.
